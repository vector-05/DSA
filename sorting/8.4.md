# 8.4: Bucket Sort
## 8.4-1: Bucket Sort Operation
<pre>
Bucket Sort Procedure
BUCKET-SORT(A, n)
    let B[0:n-1] be a new array
    for i: 0 to n-1
        make B[i] an empty list
    for i: 1 to n
        insert A[i] into B[floor(n * A[i])]
    for i: 0 to n-1
        sort list B[i] with insertion sort
    concatenate the lists B[0], B[1], ... ,B[n-1] in order
    return concatenated list

Given Array
    A = [.79, .13, .16, .64, .39, .20, .89, .53, .71, .42]
    , n = 10
Let B = [[], [], [], [], [], [], [], [], [], []]    (: list with n empty lists/arrays)
Inserting Elements
    A[1] = .79 => B[floor(10 * .79)] = B[7]
        => B =[[], [], [], [], [], [], [.79], [], [], []]
    A[2] = .13 => B[floor(10 * .13)] = B[1]
        => B =[[.13], [], [], [], [], [], [.79], [], [], []]
    A[3] = .16 => B[floor(10 * .16)] = B[1]
        => B =[[.13, .16], [], [], [], [], [], [.79], [], [], []]
    A[4] = .64 => B[floor(10 * .64)] = B[6]
        => B =[[.13, .16], [], [], [], [], [.64], [.79], [], [], []]
    A[5] = .39 => B[floor(10 * .39)] = B[3]
        => B =[[.13, .16], [], [.39], [], [], [.64], [.79], [], [], []]
    A[6] = .20 => B[floor(10 * .20)] = B[2]
        => B =[[.13, .16], [.20], [.39], [], [], [.64], [.79], [], [], []]
    A[7] = .89 => B[floor(10 * .89)] = B[8]
        => B =[[.13, .16], [.20], [.39], [], [], [.64], [.79], [.89], [], []]
    A[8] = .53 => B[floor(10 * .53)] = B[5]
        => B =[[.13, .16], [.20], [.39], [], [.53], [.64], [.79], [.89], [], []]
    A[9] = .71 => B[floor(10 * .71)] = B[7]
        => B =[[.13, .16], [.20], [.39], [], [.53], [.64], [.79, .71], [.89], [], []]
    A[910] = .42 => B[floor(10 * .42)] = B[4]
        => B =[[.13, .16], [.20], [.39], [.42], [.53], [.64], [.79, .71], [.89], [], []]

Hence we get
    B = [[.13, .16], [.20], [.39], [.42], [.53], [.64], [.79, .71], [.89], [], []]
Sorting each individual list
    B = [[.13, .16], [.20], [.39], [.42], [.53], [.64], [.71, .79], [.89], [], []]
Concatenating
    Sorted Array = [.13, .16, .20, .39, .42, .53, .64, .71, .79, .89]
</pre>
## 8.4-2: Worst Case Running Time
<pre>
For bucket sort, worst case running time occurs when all elements of input array A, end up in the same bucket in
B array, in this case, sorting is directly dependent on the running time of the algorithm used for sorting individual
buckets. By using insertion sort, the worst case running time of bucket sort comes to be O(n^2).
This can be modified to run in O(nlgn) worst case time by using radix sort instead of insertion sort.

Time Complexity of Radix Sort: Sorting n keys of length d takes O(d*n) time.
The Float Precision Dependency (d): Standard single-precision floats (float32) have 32 bits, and double-precision floats (float64) have 64 bits.If d (or bit length) is treated as a fixed constant (e.g., d = 32 bits), Radix Sort runs in O(32 * n) = O(n) time.However, if the precision required to distinguish arbitrary, high-precision floats grows with n (meaning keys require d = Omega(nlog n) digits/bits to prevent key collisions), Radix Sort's runtime becomes O(nlog n).
</pre>
