# 7.2: Performance of QuickSort
## 7.2-2: Same Value Array
<pre>
From 7.1-2, We evaluated that for all same elements in array A such that
    A = [a, a, a, a, ....]
    The partition function returns q = r
    This give us two subarrays
        Subarray 1: A[p:q-1] = A[1:r-1]
        Subarray 2: A[q+1:r] = A[r+1:r] which is empty array
        Hence we get a subarray A[1:n-1] or n-1 elements
    This procedure continues recursively untill last element.
    Each iteration takes O(n), O(n-1) time and so on..
    This gives us
        T(n) = O(n) + O(n-1) + O(n-2) + ... or T(n) = T(n-1) + T(0) + O(n)
        This indeed converges to O(n^2) time complexity!
</pre>
## 7.2-4: Banking Dilema
<pre>
The bank would use Insertion Sort as
    If people put checks in order of check number and transaction are shown in time order, all transactions also have the check numbers in monotonic order as well! Then quicksort has a O(n^2) time complexity since we have an already sorted array, and insertion sort would perform faster in this case at O(n) complexity!
</pre>
